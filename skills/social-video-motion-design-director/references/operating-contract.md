# Operating contract — measurable checks

These are workflow requirements and project heuristics, not promises of engagement or a replacement for accessible-media standards. User constraints and the actual tool's capabilities still apply.

## Intake and timing

A material/consequential decision changes a required story, audience, claims, rights, placement, approved geometry or timing, delivery constraints, cost or reversible scope in a way that could require substantial rework or cause harm. A minor stylistic choice that can be changed locally is normally non-critical. Evaluate materiality relative to the requested deliverable: a script can be drafted without choosing a frame rate; a locked frame deliverable cannot. Record reason, alternatives and who approves. For unanswered material questions, stop the blocked action; provide only safe conditional work if requested, clearly marked PROPOSED and not final.

CONFIRMED requires explicit user instruction/approval or authorized measurement of the actual input for that setting. Inferred format, agent-selected frame rate and mere source-file properties are PROPOSED unless the user authorizes them as delivery constraints. If duration is fixed but fps is not, output normalized `[start%,end%)` or duration-based seconds; no final frame count. If a user asks to see how it might look at 30 fps, mark every count/range as an **illustrative assumption** with no final approval. If neither is fixed, percentages only. Do not confuse a mathematical result under a proposal with a confirmed requirement.

For approved CFR `fps = numerator/denominator` and approved duration, record rational fps, start-inclusive/end-exclusive frames, time-to-frame rounding, transition overlaps, audio offsets and total. Define one conversion and use it throughout; e.g. `frame(t) = floor(t*fps + 0.5)` for nonnegative time, with exact rational arithmetic. This is an example policy, not an assertion that it fits every workflow. Sum ranges without accidental gaps or overlaps. Frame count and locked VO/captions are separate decisions; until a recording is aligned and checked, cue times are provisional. Video metadata alone does not establish voice synchronization.

## Claim/proof and qualifier audit

Use the required `templates/claim-proof-map.md`: one row per load-bearing claim/qualifier. List exact source quotation or source location, its scope, facts vs inference, exact VO, captions, headings, depicted proof and payoff, and check/evidence/status. Extract every qualifier affecting truth—such as “not the only,” “some,” “foreign,” dates, direction, units and uncertainty—into a checklist. Compare the exact qualifier and its subject in the VO, transcript/caption and in any on-screen statement/diagram that depicts that claim. A caption carrying the full VO can preserve a qualification even if a separate short title omits it, **only if the title is not false or misleading on its own**. Do not demand irrelevant qualifiers in unrelated scenes. If wording is not an exact match or meaning is ambiguous, label NEEDS HUMAN REVIEW; keyword presence alone never proves semantic fidelity. Verify accuracy against source material before marking a factual claim PASS.

Listening-only pass: read the complete narration in sequence with visual references hidden; write the opening question, key facts and qualifiers, causal explanation, and direct answer as a listener would hear them. Cross-check against the claim/proof map, and give exact lines for any omission/contradiction. A user-provided transcript can be inspected; an actual audio-only listening pass needs actual audio and tools. No audio? Mark actual audio pass NOT CHECKED, or NOT APPLICABLE for intentionally silent video with a reason; provide a descriptive alternative if appropriate.

## Geometry, contact and containment

Define actual rendered pixels, coordinate origin, viewport center, zoom anchor, z-order, camera, opacity, paths, easing and intentional overlaps. In the per-primitive handoff record object ID, shape, text, font size/metrics, container ID and geometry, interval, transforms, intended overlap/contact/gap, margin, test method and status. Text inside circles and other non-rectangular shapes requires a containment method: for a conservative non-rotated text bounding box in a circular region, all four transformed corners must lie within `radius − outline/2 − safety_margin`; test relevant animation frames, using actual text metrics and matching transforms. For rotated/complex shapes use the correct geometry/mask or flag NEEDS HUMAN REVIEW. Label intentional clipping and test it separately.

For connected lines/nodes, default **project tolerance** is `max(1, 2*min(output_width,output_height)/1080)` rendered pixels; it is a practical QA starting point, not a platform rule. Specify a different tolerance when necessary. Verify the rendered line segment intersects the intended node boundary, or its closest distance to that boundary is <= tolerance; endpoints intentionally inside nodes are acceptable if the segment crosses the visible outline and stacking masks the interior. Check both ends and every frame when the connection and both nodes are visible, after transforms; inspect antialiasing and masking. If a designed gap exceeds tolerance, record it as intentional and obtain approval when material. For circular moving-token contact, use `gap=distance(centers)−r1−r2`, test `abs(gap)<=tolerance` for external contact; explicitly mark designed overlaps. Test contact at the stated actual local/global frames, not at a remembered frame from another version.

## Reading, line breaks and captions

Storyboard field **Reading hold** must give text ID, intended display size, animation-settled start, earliest removal/occlusion, stable hold duration, content load, estimate method, reason for shorter holds, and rendered review status. For English non-caption text only, use `max(1.5 s, visible_characters/15 s)` as a *starting estimate* after settling; spaces count, compare against the available scene duration and competing tasks, and revise with context. This heuristic is not an empirically established minimum, not a promise of readability and not a rule for every language, literacy level, complex diagram or platform. If the user imposes a shorter duration, retain the constraint, flag the risk, and test with intended viewers. Do not lengthen or delay captions beyond their speech merely to meet the heuristic.

For English caption planning target at most two lines and roughly 32–42 characters per line as an editable starting band, not a guarantee or a hard universal cap. Respect applicable platform/language requirements. Split at natural semantic boundaries; avoid isolated short orphan words when another readable break is available; do not change spoken wording. Measure actual shaped glyph bounds against the caption panel and verified placement-safe area using the final font, size, layout and transforms; check one-line vs multi-line vertical centering and each cue at every geometry-changing state. No font/renderer? label width NOT CHECKED, do not rely on character counts as proof. After a real VO exists, align cue starts/ends to speech, include meaningful non-speech sounds and review actual timing and readable dwell; planned frame cues are provisional until then.

## Contrast: per-pair artifact

Create one row per actual applicable foreground/background pair and relevant state: scene/frame range, object ID and text/graphic, foreground, actual background/overlay/compositing, measured or planned, evidence/method, size class, target, **unrounded** ratio, status and limitation. Use WCAG 2.2 AA text contrast 4.5:1 normal or 3:1 large as the explicit reference where applicable; large text is at least 18 pt or 14 pt bold (or equivalent)—do not automatically equate video pixel size with CSS pixels or make a legal compliance finding. If large-size qualification is uncertain, use 4.5:1 as a conservative planning target and flag uncertainty. For meaningful non-text graphics consider the applicable 3:1 WCAG non-text criteria and exceptions. APCA is optional supplemental evidence, not a replacement unless project requirements specify it. Cite https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html and https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html.

No rounding a failing ratio upward (4.499 is not 4.5). For footage, gradients, anti-aliased text and fades, assess actual composited foreground/background during intended readable states and report sampling coverage. A palette calculation alone is a planning check, not full-video compliance. Use PARTIAL when some pairs/states are tested and others are not; FAIL when a tested required criterion fails; NOT CHECKED when no evidence exists.

## Integrity / byte comparison

Hash the exact supplied file bytes (including encoding and final newline); record algorithm, full hash, file name, byte length and how/when it was read. For a standalone UTF-8 JSON file embedded in Markdown, prefer an unindented fenced block with LF line endings. Define the comparison precisely: extract bytes beginning immediately after the opening ` ```json` line's terminating LF and ending immediately before the first byte of the closing fence on its own line; do not strip or reserialize. Compare those bytes directly to the file and compute SHA-256 for each byte range. Preserve the file's final LF inside the fence if present; if the file lacks a final LF or uses CRLF, embedding without transformation may be impossible—record the exact transformation, compare separately and do not claim identical original bytes. Parsed JSON equality is a separate semantic test, not proof of byte identity. If either actual byte range is unavailable, mark NOT CHECKED; never guess or publish a made-up hash.

## Sampling and revision

For **every scene** inspect at least start, midpoint and last visible frame; for every cut inspect both adjacent frames, and for every distinct object entry/exit or easing/fade event inspect start, midpoint/peak and settle/end, plus both sides of every caption-cue boundary. Deduplicate identical frames and avoid invalid negative/out-of-range frames. Sample collision-prone paths and overlapping elements more densely; run full-frame geometry checks when possible and review full playback separately at 1×, plus slowed segments when diagnosing motion. List exact frames/timecodes and evidence. If a large project or limited tools prevents this coverage, enumerate missing events and mark the broader criterion PARTIAL/NOT CHECKED, not PASS. Frame samples are not full-motion, audio or audience proof.

Priority definitions: **BLOCKER** = unsafe, materially false/unlicensed, missing required deliverable, or cannot meet core delivery/critical accessibility requirement; **MAJOR** = meaningful story, usability or quality defect without those conditions; **MINOR** = cosmetic or low-impact defect. Note uncertainty. A verified fix requires actual pre-fix evidence, actual post-fix evidence, the changed scene/time/copy or geometry, recheck scope and status. If before evidence is unavailable, mark baseline NOT CHECKED; if post evidence is unavailable, fix NOT CHECKED; do not invent or assert it was verified. “Affected” includes changed code/assets/timing, dependent cues/captions/audio, collisions and transitions, adjacent scenes, alternate aspect ratios and final export. Use the change-log template.
